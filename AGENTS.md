# Правила проекта

Коротко: текст — компактно и конкретно, релиз — `setup.exe` плюс zip,
версия — только по команде «выложи новую версию».

## Текст: README, docs, GitHub

- `README.md` — только то, что нужно для старта: что это, установка,
  возможности, управление, где данные, сборка, структура. Ориентир — 150 строк.
- Технические подробности — в `docs/`: `rendering.md` (GPU-рендер, нагрузка,
  статистика), `network.md` (буфер, «Авто»-качество, пинг), `subtitles.md`
  (захват, распознавание, перевод). Новый большой раздел — новый файл в `docs/`.
- Новая пользовательская функция → строка в README и `docs/` + запись в
  `CHANGELOG.md` (`[Unreleased]`, раздел «Добавлено»). Исправление поведения,
  даже без новой функции, тоже попадает в `CHANGELOG.md`.
- Формулировки одинаковые в README, `Cargo.toml` (`description`), описании
  репозитория и заметках релиза.
- Стиль: одна мысль — одно предложение. Без «мы хотели бы», «стоит отметить».
  Конкретика: числа, имена файлов, команды. Не дублировать одно и то же в
  README и docs — в README ссылка.

## Версия и релиз

- Версию в `Cargo.toml` поднимать **только** по команде «выложи новую версию»:
  `patch` — исправление, `minor` — новая функция, `major` — ломающее изменение.
- Релиз всегда содержит два файла:
  `twitch_mini_player-<версия>-setup.exe` (Inno Setup, per-user) и
  `twitch_mini_player-<версия>-windows-x64.zip` (портативный).
- Заметки релиза начинаются с двух ссылок на эти файлы, дальше — 2–3 строки
  о требованиях и изменениях.

## Сборка установщика

```powershell
cargo build --release --locked
powershell -ExecutionPolicy Bypass -File scripts\fetch-vendor.ps1

# ISCC лежит в папке Inno Setup 6: Program Files (x86) или %LOCALAPPDATA%\Programs
$iscc = 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
& $iscc /DMyAppVersion=0.18.0 installer\twitch_mini_player.iss
# результат: dist\twitch_mini_player-0.18.0-setup.exe
```

CI делает то же самое и прикрепляет оба файла к релизу.

## Код

- Строки интерфейса, комментарии и doc-комментарии — по-русски.
- Ошибки — `Result<_, String>` в стиле проекта; без `unwrap()` там, где
  пользователь может увидеть панику.
- Сеть, `streamlink`, захват звука и распознавание — в фоновых потоках,
  общение через `mpsc`-каналы.
- Windows-специфичный код — под `#[cfg(windows)]`.
- `scripts\*.ps1` — UTF-8 **с BOM**: PowerShell 5 без BOM читает как ANSI и
  ломает кириллицу в путях.
- Внешние библиотеки ищутся динамически (`libmpv-2.dll`, `whisper.dll`,
  `onnxruntime.dll`): без них плеер работает как обычно.
